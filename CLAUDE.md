# CLAUDE.md — clarity-examples

Example code for the Clarity replay parser. Gradle (Kotlin DSL), Java 21.

## Build / run
```bash
./gradlew :<subproject>:<exampleName>Package   # uno-jar → <sub>/build/libs/
./gradlew :<subproject>:<exampleName>Run --args "path/to/replay.dem"
./gradlew build
```

Leaf-name (unqualified) form works when the name is unique across
subprojects. Tasks are generated by the `examples-convention` plugin for
any `<subproject>/src/main/java/.../<name>/Main.java`.

## Layout gotchas
- Convention plugins live in `build-logic/` (composite included build) —
  **not** `buildSrc/`.
- `replays/` → `/home/spheenik/projects/replays`. Examples take a replay
  path as first arg. (Replay-picking guidance lives in memory.)

## Subprojects
| Subproject | Purpose                          | Java package               |
|------------|----------------------------------|----------------------------|
| examples/  | teaching code                    | `…clarity.examples.<name>` |
| repro/     | issue reproducers                | `…examples.repro.<name>`   |
| dev/       | maintainer diagnostic tools      | `…examples.dev.<name>`     |
| shared/    | shared components (ReplayChooser)| no per-example tree        |

## Upstream
Parser lives at `/home/spheenik/projects/clarity/clarity`. Wired in as
a Gradle **composite build** via `includeBuild("../clarity")` in
`settings.gradle.kts` (conditional on the sibling checkout existing),
so parser sources are picked up directly — no publish step needed. API
changes there should be smoke-tested against examples here.

## OpenSpec
OpenSpec changes and specs belong in the repo they describe. Changes
that touch the parser go in `clarity/openspec/`; changes that touch
examples go here. Don't let the working directory decide — move them
after creation if needed.

## Benchmarking
Throughput benchmarks live in the separate `clarity-bench` project at
`/home/spheenik/projects/clarity/clarity-bench`. See its README for
usage.
